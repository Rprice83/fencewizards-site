# Fence Wizards website

A static site generated by a small Node build, plus Cloudflare Pages Functions and a D1 database for forms.

```
site/
  build/
    pages/             one file per page (edit content here)
    partials/          hand-built HTML for the homepage, estimator and confirmation page
    lib/site.mjs       phone, email, towns, nav (change once, every page updates)
    lib/components.mjs page building blocks; see build/AUTHORING.md
    build.mjs          writes public/<path>/index.html, sitemap.xml, robots.txt
    check.mjs          link/asset/title checker
  public/              what gets deployed (the HTML in here is generated, so don't edit it directly)
    styles.css, js/, estimate/, assets/
  functions/api/       POST /api/quotes (estimator), POST /api/contact (all other forms)
  server/              backend helpers (validation, pricing, email)
  content/field-notes/ job stories as Markdown (see ../FIELD-NOTES.md)
  tools/               add-field-note-photos.py (resize photos, strip GPS)
  migrations/          D1 schema
  tests/               `npm test`
```

## Editing pages
Change the page file in `build/pages/`, then run `npm run build` (and `npm run check`). `npm run dev` builds and starts the local server.

## Run it locally
1. `npm install` (once)
2. `npm run db:migrate:local` (once, and after adding migrations)
3. `npm run dev`, then open http://localhost:8788

Without a Resend key, emails aren't sent. They're saved with each submission, and you can view the latest at
http://localhost:8788/api/dev/email-preview (or `?id=FW-...` / `?id=FW-M-...`). This needs `DEV_PREVIEW=true` in `.dev.vars`.

## Going live (Cloudflare)
1. `npx wrangler login`
2. `npx wrangler d1 create fencewizards-quotes`, then paste the `database_id` into `wrangler.toml`
3. `npm run db:migrate:remote`
4. In Resend, verify fencewizards.com, then run `npx wrangler pages secret put RESEND_API_KEY`
5. `npm run build && npm run deploy`, then connect the domain in the Cloudflare dashboard (build command `npm run build`, output `public`)
6. Do **not** set `DEV_PREVIEW` in production.

## Quote Inbox (/staff/)
Estimator quotes and form messages in one list, with status (new → contacted → quoted → won / lost), notes, history,
the customer's drawn fence on a satellite map, and Call / Text / Email buttons. Richard's notification emails link straight to each one.

**Locally** it signs you in automatically as `DEV_STAFF_EMAIL` from `.dev.vars` (localhost only): http://localhost:8788/staff/

**Security:** Cloudflare Access (Sign in with Google) guards `/staff/*` and `/api/staff/*`. The code also verifies Access's
signed token and checks `STAFF_EMAILS` on every request, so if Access were ever misconfigured the Inbox stays locked (`server/staff-auth.js`).

### Setup at launch (about 15 minutes, free for up to 50 people)
1. Cloudflare dashboard → **Zero Trust** → pick a team name (e.g. `fencewizards`). Choose the Free plan.
2. **Settings → Authentication → Login methods → Add → Google** and follow the steps (creates a Google OAuth client).
   Optionally also add **One-time PIN** for anyone without a Google account.
3. **Access → Applications → Add → Self-hosted**:
   - Name: Quote Inbox. Session duration: **1 month** (so Richard rarely has to sign in again).
   - Public hostnames: `www.fencewizards.com` with path `staff`, **and a second entry** with path `api/staff`.
     (Add the same two for the `*.pages.dev` address if you use it.)
   - Policy: Allow → Include → Emails → Richard's Google address, yours, and any employees.
   - Login methods: Google (+ One-time PIN if enabled). Turn on "Instant auth" if Google is the only method.
4. Copy the application's **Audience (AUD) tag**, then set in `wrangler.toml` (or as Pages environment variables):
   `ACCESS_TEAM_DOMAIN = "fencewizards.cloudflareaccess.com"`, `ACCESS_AUD = "<tag>"`,
   `STAFF_EMAILS = "<same emails as the policy>"`, `OWNER_EMAILS = "<Richard>,<you>"`, `STAFF_NAMES = "<email>=Richard,..."`.
5. `npm run db:migrate:remote`, deploy, then open https://www.fencewizards.com/staff/ on Richard's phone,
   sign in with Google, and use Share → **Add to Home Screen** so it opens like an app.

To add or remove someone: update the Access policy **and** `STAFF_EMAILS`. Removing someone from the Access policy locks them out immediately.
